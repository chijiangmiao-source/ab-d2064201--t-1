# 机载维护站 · 读卡器升级指令 T=1 隔离复核台

审查员在页面填写**审计标识**，按捕获顺序录入不超过 64 条**带方向**的十六进制
T=1 原始块（`reader` / `card`），服务端冻结裁决并持久化证据。页面本身不做任何
裁决计算，所有结果均经真实 HTTP API 读取。

## 能力

- 帧校验：NAD（拒绝保留值 0xFF）、PCB 保留位与类型、LEN（拒绝 0xFF）、INF 跨度、LRC 逐块校验
- I 块：发送序号 N(S)、M 位链式组装为完整 APDU（合法重复**不重复拼接**）
- R 块：ACK 的 N(R)=下一期望序号；NAK 的 N(R)=被请求重传的未确认序号；序号错误/无的放矢均拒绝
- S 块：WTX（0xC3/0xE3）与 IFS（0xC1/0xE1）请求/应答的类型、方向、倍率匹配；
  匹配往返后继续处理后续块，挂起期间任何 I/R 块均拒绝
- 双向独立维护：发送序号 V(S)、最新未确认 I 块、链内片段、等待扩展状态（每步状态快照）
- 稳定定位：LRC 错误、非最近块重复、错误 R 块序号、越界 INF、错误 WTX 应答、
  不可能序号推进等，一律返回**首个**违规原始块的 1 基序号
- 冻结审计：相同标识+相同捕获返回原冻结结果（幂等，200）；改动任一块 → 409 冲突，
  原结果仍可读取且永不被覆盖；落盘持久化（`AUDIT_FILE`，原子写入）

## 运行

```bash
npm start                 # 默认 0.0.0.0:8080
PORT=9090 npm start       # 可配置端口
curl http://127.0.0.1:8080/health
```

- `GET  /health`：健康响应
- `GET  /api/audits`：已冻结审计清单
- `GET  /api/audits/:id`：读取冻结结果（裁决、完整 APDU、逐步序号、重传依据、状态快照）
- `PUT  /api/audits/:id`：提交/冻结（body：`{reviewer?, blocks:[{direction, hex|bytes}]}`）

## 验收（构建检查 + 代码测试 + API/HTTP 冒烟，退出码报告结果）

```bash
bash scripts/verify.sh    # 或：npm run verify；PORT 可配置
```

Compose 内的可执行 `verify` 入口：

```bash
docker compose up -d web              # 服务（含健康检查）
docker compose run --rm verify        # 执行验收并以退出码报告
```

## 测试覆盖（`node:test`，41 项）

- 合法重传：NAK 后最近未确认 I 块的合法重复及后续确认通过，APDU 只拼接一次
- 非法等待扩展：应答类型不符、倍率不符、方向不符、无请求的应答、倍率 0、挂起期间来块
- 链式组装、双向序号、错误 R 块序号、非最近块重复、不可能序号推进、越界 INF、LRC/NAD/PCB
- 冻结审计：同标识同捕获返回原结果、改动冲突且原结果可读、拒绝同样冻结、落盘重载
- HTTP API：健康、页面、冻结/重放/冲突/读取、非法 WTX 冻结为拒绝
